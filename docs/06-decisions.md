## ADR-001: Pin to the predecessor app's Expo SDK 57 dependency matrix

**Date:** 2026-08-15 · **Status:** accepted

**Context.** The daybot mobile app (same operator, prior project) shipped to the App Store on
an exact dependency matrix: Expo SDK ~57.0.8, React Native 0.86.0, React 19.2.3, expo-router
~57.0.8, reanimated 4.5.0 + worklets 0.10.0, gesture-handler ~2.32.0, screens ~4.26.0,
safe-area-context ~5.7.0. That combination is known-good under review, on devices, and under
EAS builds. RN/Expo version skew is the single most common source of phantom build breakage.

**Decision.** Every dependency RacquetAI shares with that app is pinned to the same version.
Packages the predecessor didn't use (expo-camera ~57.0.3, expo-video ~57.0.2, expo-file-system
~57.0.4, expo-media-library ~57.0.4) are added at the SDK-57-matched versions `npx expo install`
resolves. One deliberate divergence: `jest-expo` is pinned exactly to 57.0.2 — 57.0.4 raised its
`@react-native/jest-preset` peer to ^0.86.2, which conflicts with RN 0.86.0's peerOptional pin;
57.0.2 is what the predecessor's lockfile actually resolved to.

**Consequences.** Upgrades happen as a deliberate matrix bump (all of Expo + RN + reanimated
together), never one package at a time.

## ADR-002: `ios.supportsTablet` true from day one

**Date:** 2026-08-15 · **Status:** accepted

**Context.** The predecessor app's 1.0 (build 6) left `supportsTablet` unset, shipped
effectively iPhone-only-stretched, and was rejected under App Review guideline 4 ("crowded,
laid out, or displayed in a way that made it difficult to use") on iPad. The fix cost a review
round-trip at the worst possible time.

**Decision.** `supportsTablet: true` plus the full `UISupportedInterfaceOrientations~ipad`
array is in `app.json` from the first commit, and `src/theme/layout.ts` ships the
centred-column caps (`CONTENT_MAX_WIDTH` 760 / `FORM_MAX_WIDTH` 560) that make iPad render
readable columns while leaving iPhone byte-for-byte unchanged.

**Consequences.** Every screen must build on `Screen`/`column()`; docs/05-testing.md adds an
iPad simulator pass to UI changes. Recording UX on iPad is a real design question (people do
film matches with iPads) — a nice problem to have, not a rejection.

## ADR-003: expo-camera over react-native-vision-camera for v0

**Date:** 2026-08-15 · **Status:** accepted

**Context.** v0 needs: portrait video capture with audio, a preview, start/stop, and saving
files. react-native-vision-camera offers frame processors (per-frame JS/worklet access) that
the future on-device ML scoring will likely want, but it is a custom native module with its own
build-config surface and upgrade cadence.

**Decision.** `expo-camera` for v0. It covers capture entirely within the managed workflow
(config-plugin permissions, no prebuild customisation), stays inside the pinned SDK-57 matrix
(ADR-001), and keeps CNG intact (ADR-004). No frame processors are needed until scoring runs
on-device — v1 scoring can even run server-side or post-hoc over recorded files without any
per-frame camera access.

**Consequences.** When live on-device scoring lands, vision-camera is the planned upgrade
path: it slots in via a dev build without ejecting (Expo supports custom native modules), and
the capture UI sits behind `src/features/recording/`, so the swap is contained to one feature
folder. Revisit in the ADR when feat/ai-scoring commits to an on-device model.

## ADR-004: Managed workflow with `ios/` gitignored (CNG)

**Date:** 2026-08-15 · **Status:** accepted

**Context.** The predecessor app also gitignored its generated native folders
(`/ios`, `/android` under "generated native folders" in its `.gitignore`; `git ls-files`
confirms zero tracked entries). CNG worked for it: no native-project diffs to review on SDK
bumps, and no hand-edits to an Xcode project that could silently diverge from `app.json`.
*(Correction 2026-08-15: this paragraph originally claimed the predecessor committed `ios/`;
verification against the source repo showed it did not — see docs/02 §8.)*

**Decision.** Continuous Native Generation: `ios/` and `android/` are build artifacts,
regenerated by `expo prebuild` (implicitly via `expo run:*` and EAS). Both are gitignored.
All native configuration flows through `app.json` and config plugins — permission strings,
orientation, bundle identifiers, splash, icons.

**Consequences.** No hand-edits to native projects, ever — anything native goes through a
config plugin or an `app.json` key. If a change genuinely can't be expressed that way, that's
the trigger to write a custom config plugin, not to commit `ios/`. `npx expo prebuild --clean`
is always safe to run.

## ADR-005: Patch-bump the matrix to Expo's blessed SDK 57 versions

**Date:** 2026-08-15 · **Status:** accepted · **Amends:** ADR-001

**Context.** First simulator run in Expo Go segfaulted natively (`EXC_BAD_ACCESS` in
`worklets::JSIWorkletsModuleProxy` via Hermes) on every launch. Expo Go for SDK 57 embeds
the *native* side of reanimated 4.5.1 / worklets 0.10.1; our JS side was pinned at
4.5.0 / 0.10.0 per ADR-001. Worklets requires its JS and native halves to match exactly —
a patch-level skew is enough to crash. The predecessor never hit this because it only ran
as a native dev-client build, never inside Expo Go.

**Decision.** Align to what `npx expo install --check` blesses for SDK 57 today:
react-native 0.86.2, react-native-reanimated 4.5.1, react-native-worklets 0.10.1,
jest-expo ^57.0.4 (+ explicit `@react-native/jest-preset` ^0.86.2 devDependency to satisfy
its peer), @types/jest 29.5.14. This also dissolves ADR-001's jest-expo 57.0.2 divergence:
that pin existed only because of RN 0.86.0's peerOptional conflict, which 0.86.2 resolves.

**Consequences.** ADR-001's matrix-not-package upgrade policy stands — this was one
coordinated bump, verified with the full check suite (tsc, lint, 89/89 jest, expo export)
plus a live Expo Go simulator pass of all four tabs in light and dark mode. When a native
dev-client build ships, Expo Go alignment stops being a constraint, but staying on the
`expo install --check` versions remains the default.
